# 南京麻将 · 好友局（Sites 版）

四人南京麻将敞开头，保留精绘麻将牌、邀请链接、匿名座位、详细计分和 45 秒单局结算。当前规则 V1.0.10：普通七对加40，可叠加门清；七对、两个花且无其他加分的点炮为128分。三嘴后的第四次碰杠机会由玩家选择特殊胡，可放弃，不成立该次副露、不计该次杠分、不补牌。三清和全球继续保留。

升级前 V1.0.8 存档中的整将继续按原三嘴流程完成，再来一将时切换当前规则；七对加分纠正适用于更新后新生成的结算，历史分数和已保存付款保持原样。V1.0.9 存档可直接加载，详见 [本地运维](docs/local-operations.md)。

## 本地预览

使用 Node.js 24 和 npm：

```sh
npm ci
npm run build
npm run db:local
npm run dev
```

打开 http://127.0.0.1:3105。四人测试请使用独立浏览器配置；同一浏览器的标签共享身份，新页面会接管旧页面。

## 云端架构

- React 前端通过同源流式连接接收更新；只传输变化后的安全视图，出牌独立发送。连接异常时自动回退到短轮询。
- Cloudflare Worker 复用原有规则引擎与权威牌桌逻辑。
- 普通同步使用两条轻量 SQL 批量读取一致快照并节流心跳写入；动作通常两次往返即可确认，旧刷新响应不会覆盖动作结果。
- D1 保存身份、房间、私有牌局和操作回执；事务及版本校验防止并发覆盖和重复计分。
- HttpOnly Cookie 保存匿名身份。邀请链接只含房间号；清除浏览器数据后无法找回原座位。
- 玩家离线后暂停，断线检测最多约 6 秒；四人回来继续。离线期间冻结结算倒计时。
- 每个玩家仅收到自己的安全视图；牌墙、他人暗手和内部决定不会发送到浏览器。

本地预览数据位于 `.wrangler/state/`，不会上传。生产数据使用 Sites 绑定的 D1，不能用原 Node SQLite 备份脚本管理。

## 检查与发布

```sh
npm run format:check
npm run lint
npm run typecheck
npm run typecheck:cloud
npm test
npm run test:cloud
npm run build
npx playwright install chromium
npm run test:e2e
```

`cloud/` 包含后端，`db/schema.ts` 定义表，`drizzle/` 保存增量迁移。修改表后运行 `npm run db:generate`，审查迁移并在本地验证。不要修改已发布的迁移。

构建产物为 `dist/server/`、`dist/client/` 和 `dist/.openai/`。通过 Sites 工作流推送对应源代码、保存版本并发布；复用 `.openai/hosting.json` 的项目身份。不要将数据库或凭据提交到仓库。

自动测试覆盖四浏览器开房、操作、刷新、断线恢复和再来一将。四位真实玩家的完整一将体验仍需实际试玩验证。

## 退出与超时

房内每位玩家均可确认后提前结束本将，保留已结算分数。暂离保留座位并暂停牌局。

房间在最后一次有效玩家命令 30 分钟后失效，心跳、刷新与结算倒计时不会续期。在线页面会在下一次同步时自动返回大厅；全员离线时，下一次访问会先清理过期房间。解散释放全部座位，未完成牌局不再恢复，可重新创建同一自定义房间号。

每局结算提供“开始下一把”：显示已准备人数，四人确认后立即开始；未全员确认仍按原有 45 秒倒计时推进，掉线时暂停。确认状态支持刷新恢复，仅对当前结算有效。
