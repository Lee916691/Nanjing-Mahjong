# 南京麻将 · 好友局（Sites 版）

支持双人和四人南京麻将敞开头，保留精绘麻将牌、邀请链接、匿名座位、详细计分和 45 秒单局结算。四人规则仍为 V1.0.11：第16庄次不再因普通自摸、暗杠或明杠/补杠次数单独续庄，大牌及其他续庄条件保留。普通七对加40，可叠加门清；七对、两个花且无其他加分的点炮为128分。三嘴后的第四次碰杠机会由玩家选择特殊胡，可放弃，不成立该次副露、不计该次杠分、不补牌。三清和全球继续保留。

创建房间时可选择“双人敞开头”（V1.0.12），默认仍为四人。双人使用完整144张牌、8个有效庄次；
胡牌和包子付一份，抢补杠取消×3，暗杠实际20分，停用跟打一圈与四风归齐；真实自摸及按自摸
结算的包子加2软花一次。两人准备后开局，面对面牌桌，双方确认可提前开始下一手，再来一将保留
模式。规则见[第29章](docs/nanjing-mahjong-rules.md)，完成情况与验收见[双人模式设计](docs/two-player-mode.md)。

升级前 V1.0.8 存档中的整将继续按原三嘴流程完成，再来一将时切换当前规则；七对加分纠正适用于更新后新生成的结算，历史分数和已保存付款保持原样。V1.0.9/V1.0.10 存档可直接加载，后续未完成手牌使用新的第16局续庄判断，详见 [本地运维](docs/local-operations.md)。

## 本地预览

使用 Node.js 24 和 npm：

```sh
npm ci
npm run build
npm run db:local
npm run dev
```

打开 http://127.0.0.1:3105。双人/四人测试均请为每位玩家使用独立浏览器配置；同一浏览器的标签共享身份，新页面会接管旧页面。

## 云端架构

- React 前端通过同源流式连接接收更新；只传输变化后的安全视图，出牌独立发送。连接异常时自动回退到短轮询。
- Cloudflare Worker 复用原有规则引擎与权威牌桌逻辑。
- 普通同步使用两条轻量 SQL 批量读取一致快照并节流心跳写入；动作通常两次往返即可确认，旧刷新响应不会覆盖动作结果。
- D1 保存身份、房间、私有牌局和操作回执；事务及版本校验防止并发覆盖和重复计分。
- HttpOnly Cookie 保存匿名身份。邀请链接只含房间号；清除浏览器数据后无法找回原座位。
- 玩家离线后暂停，断线检测最多约 6 秒；该模式的全体玩家回来继续。离线期间冻结结算倒计时。
- 每个玩家仅收到自己的安全视图；牌墙、他人暗手和内部决定不会发送到浏览器。

本地预览数据位于 `.wrangler/state/`，不会上传。生产数据使用 Sites 绑定的 D1，不能用原 Node SQLite 备份脚本管理。

## 检查与发布

```sh
npm run format:check
npm run lint
npm run typecheck
npm run typecheck:cloud
npm test
npm run test:cloud
npm run build
npx playwright install chromium
npm run test:e2e
```

`cloud/` 包含后端，`db/schema.ts` 定义表，`drizzle/` 保存增量迁移。修改表后运行 `npm run db:generate`，审查迁移并在本地验证。不要修改已发布的迁移。

构建产物为 `dist/server/`、`dist/client/` 和 `dist/.openai/`。通过 Sites 工作流推送对应源代码、保存版本并发布；复用 `.openai/hosting.json` 的项目身份。不要将数据库或凭据提交到仓库。

自动测试覆盖双人/四人开房、操作、刷新、断线恢复和再来一将，以及合法夹具中的双人8庄和末庄续庄。
两位/四位真实玩家自然完整一将、实际触屏等体验仍待试玩验证。新存档格式2兼容旧四人档读取，
下一次正常保存升级；旧程序不能读取新档，回滚须使用升级前备份，详见[运维说明](docs/local-operations.md)。

## 退出与超时

房内每位玩家均可确认后提前结束本将，保留已结算分数。暂离保留座位并暂停牌局。

房间在最后一次有效玩家命令 30 分钟后失效，心跳、刷新与结算倒计时不会续期。在线页面会在下一次同步时自动返回大厅；全员离线时，下一次访问会先清理过期房间。解散释放全部座位，未完成牌局不再恢复，可重新创建同一自定义房间号。

每局结算提供“开始下一把”：按模式显示确认人数，双人双方/四人全员确认后立即开始；未全员确认仍按原有 45 秒倒计时推进，掉线时暂停。确认状态支持刷新恢复，仅对当前结算有效。
