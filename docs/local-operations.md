# 本地运行与存档

## 环境

Node.js 24，使用仓库锁文件安装依赖。执行 `npm run build` 后，`npm start` 由一个进程提供网页、API、Socket.IO。生产启动不依赖 tsx 或开发服务器。

环境变量：HOST（默认0.0.0.0）、PORT（默认3000）、DB_PATH（默认data/mahjong.sqlite）、PUBLIC_ORIGIN（反向代理后明确配置对外源）。HTTPS部署时 PUBLIC_ORIGIN 必须是 https，以启用 Secure Cookie。

首版仅一个服务实例访问数据库；不要把多个实例放到负载均衡后面。

## 在线一致性备份

在仓库根目录运行：

```sh
npm run backup -- backups/friends.sqlite
```

备份使用 SQLite backup API，可在游戏运行时执行；目标不能覆盖现有文件。备份包括匿名身份、房间、牌局、已结算事件和命令回执，按私有文件保存，不发送给玩家或放入网页目录。

不要在运行中只复制主数据库文件，因为已提交事务可能仍位于 WAL 文件。

## 恢复

1. 停止游戏服务。
2. 保留原数据库及其相关文件，不直接覆盖。
3. 将备份复制到一个新的文件路径，例如 data/restored.sqlite。
4. 修改 .env 中的 DB_PATH 为这个新路径。
5. 启动服务，用原地址和原浏览器重新连接。
6. 四人回来后检查座位、手牌、分数和有效庄次，再继续。

使用同一地址和端口可保留浏览器 Cookie。更换 localhost、局域网IP或域名可能导致浏览器不发送旧身份。

存档记录格式与规则版本；不兼容时停止启动并报告错误，不自动重置。备份恢复到较早时刻会回退该时刻之后的所有动作，恢复前通知玩家。

## 日常检查

- /health 返回 status: ok。
- 房间中四个连接标记都在线。
- 浏览器断网后其他玩家能看到暂停提示。
- 更新代码前备份，不在进行中的牌局里直接运行不兼容版本。
- 生产日志不包含完整暗手、牌墙或匿名凭据。

## V1.0.9 三嘴规则升级

新开一将采用特殊胡方案。V1.0.8存档中的整将继续按原自动碰杠结算流程运行，直到结束或玩家主动提前结束；再来一将时使用当前规则。加载只补充内部兼容标记，不重算历史分数、不清空数据库、不改变已收集的响应。新规则内部三嘴状态不对客户端公开。发布前仍需备份现有存档。

## V1.0.10 七对加分纠正

普通七对加分由50纠正为40。更新后新生成的付款和计分说明使用纠正值（包括V1.0.8兼容整将），历史累计分数、已保存付款与说明快照保持原样。V1.0.9房间只升级版本标记，不重建手牌或响应窗口。SQLite存档接受V1.0.8、V1.0.9和V1.0.10，D1沿用相同房间兼容入口，无数据库结构迁移。
